# AIMovieStorage project work

Use this skill when the user wants to create or continue an AIMovieStorage drama, music video, scene, or shot from a Codex chat. The short Korean request "사용자올제 <이름> 프로젝트 만들어줘" means to work in the AIMovieStorage project named <이름>; "이어줘" means to continue it. First inspect the app and continue an existing matching project instead of creating a duplicate. Ask which project only if the app lists several plausible matches and the choice changes the work.

## Connect and inspect

The desktop app must be running. App Control starts automatically unless the user turned it off in **Settings → 대화로 앱 조종하기**; if off, use **앱 조종 켜기**. Connect Codex to the app's local `aimoviestorage` MCP server using the command shown in that Settings screen. The installed skill does not configure Codex MCP or start the app for the user. Check the connected server's `tools/list` and `app_status`; available commands depend on the installed edition and version. If it is unavailable, say what connection step is missing, and continue any useful offline preparation.

Start each work session with `projects_list`, then `project_get` for the chosen project. Read current IDs, values, and revision before editing. After the user edits in the app, read `project_changes` or `composition_changes` since the last revision; if history is incomplete, get a fresh full snapshot. Incorporate those edits instead of replaying stale commands. Pass the current `expectedRevision` to writes. A revision conflict means read again and re-plan, not blind retry.

Before generating images or videos, read `creation_options` for the project's actual app routes and selected models. If the user has not chosen a model or route, ask once for the image and video choices that the work needs; do not ask again for every cut. Offer local generation, the app's Magnific «구성», and configured ComfyUI only where available. If the user says to decide everything, choose from the app's current settings and task needs, then state which model and route you chose. Save an image model on each relevant character/background with `project_update` (`character.update`/`background.update`, `fields.promptModel`); save a video model with `project.update`, `fields.videoModel`. Read the new revision back before `prompt_prepare` or Magnific composition, so the app's prompt rules and generator use that choice. A prior choice persists for this project until the user changes it. For local generation, pass the chosen `engine` to `media_generate`; for ComfyUI, select an actual configured workflow. Do not infer lower cost or better quality without a measured comparison.

## Build and verify

When planning the whole film, use `project_update` `scene.move` and `cut.move` to set playback/storyboard order by zero-based position. The app renumbers cuts after a move while retaining their saved images, videos and compositions. Read the new revision before the next edit; do not infer order from titles alone.

For a revised shot prompt, call `project_prompt_history` with the saved target to list earlier versions, then pass one `entryId` to read its full bilingual text. Continue from the latest app state and current references. If the user chooses an older version, apply it through `project_update` `prompt.apply` with the current revision so the old and new versions stay in the card history.

Start a creative editing pass with `project_prompt_status` and paginate until every character, background, storyboard, cut image and cut video prompt slot is accounted for. It reports Korean/English presence and history without sending large prompt bodies. Resolve empty slots and review rule-built drafts through the app's exact `prompt_prepare` → `project_update` `prompt.apply` path. For music projects, inspect `bgm_get` and use `bgm_prompt_prepare` for each track.

Treat the controller as the app's editing interface, including shot planning. Inspect the live `app_status` command list and `composition_get` available IDs before changing rooms, characters, props, camera paths, motion keys, or timeline music. `composition_apply` accepts typed edits to those saved states; `composition_commit` persists the result. Use `project_update` for project genre/style/era, card profiles and reference analysis, cut cast and chosen reference images, and image marks (anchors and motion regions). Link a generated image to a character/background reference with `reference.link`; move or unlink only that reference without deleting the source asset. When a scene has primary cut images or saved composition guides, `storyboard_bake` builds the same storyboard sheet and bilingual rule prompt as the app. Then use `prompt_prepare` for the scene video request.

For a character or background composite sheet, read the saved card image IDs first. Use `project_update` command `sheet.layout.upsert` to create or revise the project's shared layout in pixel coordinates, then `sheet.fill` to select this owner's image IDs for those slots. Re-read the revision and call `sheet_bake` with a stable `operationId`. It uses the app's sheet renderer, saves the image in the project folder, and keeps an editable sheet snapshot. Review the output before using it as a generation reference. The current controller creates a new sheet; replacing an old sheet remains an app UI operation.

For a new screenplay, `bootstrap_input_update` stores the source and desired counts in the app's AI batch creation input. Use `bootstrap_prompt_prepare` in order for `outline`, `details`, and `shots`; pass each previous answer into the next request. These requests use the app's batch templates and already uploaded reference files. Inspect the full cast, locations, cuts, and shot plans before `bootstrap_apply` with a stable operation ID and its input fingerprint. Append by default. Replace removes existing scenes and cards without images; use it only when explicitly requested and set `confirmedReplace` after reviewing the effect. `bootstrap_apply` uses the app's parser and composition builder, records the batch in app history, and rejects a stale project revision. It returns the fourth-stage `promptTargets`: for each character, background, cut image and cut video, call `prompt_prepare` and apply all four Korean/English positive/negative fields with `project_update` `prompt.apply`. Read the new revision after every card. `bootstrap_prompt_targets` persists the worklist and remaining count for a later chat. Do not mistake the three-stage draft prompts for completed detailed prompts. Afterward, open individual cuts to refine room geometry, multiple camera moves, motion, keys, and music using `composition_apply`, then commit and render.

If the screenplay or music video has local reference images or footage, use `bootstrap_reference_register` with a stable operation ID and a note explaining exactly what to borrow. The app copies them into the project and assigns `@ref_img_N` or `@ref_mov_N`; use these exact tags in the batch prompts. `bootstrap_reference_update` changes a note or removes a file from the batch request while preserving the original project file. Check the returned input fingerprint before each next batch phase.

For the other app prompt buttons, use `prompt_prepare_extra` (profile, reference analysis, first reference, background faces), `natural_prompt_prepare` (spoken description/acting/background motion/VFX), or `bgm_prompt_prepare` for style and lyrics. Apply each result to the indicated typed fields with the returned revision, preserving distinct Korean and English text. These tools assemble the app's current request; they do not themselves call an LLM API or save the model's reply. Read back saved fields and prompt history after applying. If the installed server lacks one of these commands, report that exact gap instead of making a generic prompt and claiming app parity.

Use `project_update` for story, characters, backgrounds, scenes and cuts. For each character, background, cut image, cut video or scene video prompt, call the app's `prompt_prepare` first. It returns the same current request text, selected blueprint, model/platform rules and reference images as the app's API prompt button. Follow that request to write **four distinct fields** (`ko`, `en`, `negativeKo`, `negativeEn`), then save them with `project_update` command `prompt.apply` and the returned revision. If the user edits the app meanwhile, reread and prepare again. Do not make a separate generic prompt, use a provider's direct MCP prompt path, or paste English into the Korean field. The app saves both old and new prompts in its card history; read back the result. This applies to Claude as well as Codex.

For the shot planner, open the appropriate cut, apply supported `composition_apply` commands, capture when needed, and commit the composition. The composition's in-memory state and the saved project are distinct; verify `persisted`/`persistedLatest` and read the resulting state. For reference clips, use `composition_export_video` and check `job_get` until the file and project association are confirmed. If the timeline has music, the export should carry the same time segment of that music; inspect the returned audio path before a Magnific composition.

Build the complete shot in the app before generating a final image or video. Read `composition_get` for available character, background, image, video, swap and preset IDs. Use `composition_apply` to create rooms, assign six faces or a panorama, place and pose characters, attach props, link swap sheets, plan camera moves and their keys, and set timeline motion and occlusion keys. Capture the guide and background plate, inspect them, then commit. For another cut, a saved room can be added with `project_update` command `room_preset.save_from_cut` after the source composition is committed, then placed with `room.preset_apply`. `composition_glb_import` copies a local animation model into the project before `glb.update` edits its timing. Choose saved BGM with `composition_music_use` or import a local song with `composition_music_import`; the app measures the file instead of accepting a guessed duration. For dense motion-capture keys, `composition_motion_cleanup_prepare` returns the same AI request as the app, and `composition_motion_cleanup_apply` applies reviewed decisions or the app's automatic cleanup. Re-read the composition revision after every manual edit and before commit.

For a music-video dance, use `composition_music_analyze` after placing the song; inspect beat confidence and first beats. Correct `music.update.downbeatIndex` if needed, then use `music.split_detected_bars`. Timing analysis is not choreography. If the installed server lists `kimodo_install` and `kimodo_generate`, use them to install the isolated environment and generate a SOMA-RP/SEED v1.1 phrase with an English motion description, explicit duration, seed and encoder device. Gated Llama access requires the user's approved Hugging Face token in app Settings. Use a stable operationId, inspect job_get, and verify the saved source, original BVH and generation metadata. Alternatively use `mocap_import_kimodo` for an external SOMA BVH or capture a dance reference. Call `composition_apply_dance` with source ID, person number, placed character IDs and intended music sections. This repeats pose keys while preserving placement and camera keys. Review musicality, spacing and abrupt transitions in the app before commit. Kimodo does not take audio input; installation or synthetic tests do not prove actual GPU generation quality. Older apps without the new tools require external BVH generation.

When creating a character through `character.add`, inspect the app's selected character reference blueprint and send its panel IDs in `fields.blueprint` if the shot needs a different set. After the card is saved, use `prompt_prepare` and `prompt.apply` so the selected panels and current project context become part of the request. On `character.update`, preserve manually edited identity details and prepare the prompt again if the blueprint changes. Read back the character's blueprint and both prompts, generate or register the image, then mark the approved image primary. Selected chips alone are not a generated reference sheet.

For `media_generate` targeting a character, the app adds the current blueprint panels to the worker prompt and records the effective prompt on the result image. Inspect the generated file before choosing it as primary. The current local image workers do not use an existing character image as an editing reference, so do not claim that a locally regenerated sheet preserves an approved face merely because an image ID was supplied. Use a verified reference-editing workflow and `media_register` when exact identity must be retained.

When adding a cut, set `characterIds` to the IDs of people actually visible in that shot; use `[]` for an object or empty-space shot. A name in dialogue, the scene cast, or a neighboring clip does not by itself make that person visible. This field is required in current `cut.add` requests. If an image exists for a selected character, verify that both the saved image and video prompts contain its actual `@` reference after the update. Repair older cuts using the cut's explicit visible-cast evidence and current asset paths; do not attach every scene character to every cut.

Write Korean and English together for each cut image prompt (`promptKo`/`promptEn`), negative prompt (`negativeKo`/`negativeEn`), and video prompt (`videoPromptKo`/`videoPromptEn`). Use `prompt_prepare` and `prompt.apply` for generated prompts, including a second request on the same shot. The controller records previous and new versions. Do not send only the English field because the Korean editor then stays empty. If a cut already has English text but lacks Korean, update the Korean side while preserving the existing English text and any `@` references. The controller rejects a cut prompt edit that would leave just one language populated; prepare both texts before sending a new cut.

For scene storyboards, provide Korean `storyboardPromptKo` and English `storyboardPromptEn` as separate prose. The app rejects a Korean field whose body is mostly English, including cut and character prompts. Do not copy an English scene summary into the Korean field just to make it nonempty; translate the action, dialogue guidance and camera instructions into natural Korean, then read back both fields.

Local image/video/music generation and ComfyUI can be requested through the app only if the installed server lists their tools. Generation submission is not completion: inspect the task, inspect its saved project target, and do not duplicate a job after a lost response. For the app's Magnific image path, use `magnific_sheet_compose_preview` for a character/background or `magnific_compose_preview` for a cut, then `magnific_compose` with its preview ID. These commands use the app's saved prompt, selected references and image model; the background command also follows the app's aspect ratio. They prepare/upload a board but do not press Generate or spend credits. Confirm actual provider output separately before recording it as a result. For music-video composition, keep the exact timeline segment in the reference MP4 and use its matching audio file as a separate audio reference with music enabled; mention both references in the prompt with their actual `@` names. Do not substitute the full song for a 15-second segment.

Before composing a background, read its `blueprint` in `project_get`. The default exterior master chip `master-birdseye` makes a 1:1 image; a regular 16:9 eye-level image uses `view-eye-exterior`. Set the intended chip with `project_update` and regenerate or edit the bilingual prompt accordingly. Check every preview's `aspectRatio` against the requested output before composing or running a batch. A ratio written only in prose does not change the generator setting; the controller rejects an explicit mismatch.

For several Magnific images, set each image preview's `count` to the requested number of choices (default four, maximum four). Inspect every preview, then send their IDs in canvas order to `magnific_compose_batch` with one stable `operationId`. If the user asked the app to run them through Magnific Desktop, set `runAfterCompose: true`: the app checks that each **new** generator shows 2K and the infinity/no-credit icon, selects only that generator, and submits each group in order. It stops rather than running any existing node or a node that lacks the no-credit indication. Read `job_get` and reconcile a partial batch on the board before another submission; a submitted job is not a completed image. Review finished candidates with `magnific_results_list` and register only selected creation IDs using `magnific_result_register`, carrying the saved Korean and English prompts. Mark the approved representative with `makePrimary`; verify the project shelf and revision. Never use `Ctrl+A` on a board with earlier generators.

Magnific's published Acceptable Use Policy restricts external automation, including automatic generation. Confirm the account's permitted integration route with Magnific before using `runAfterCompose` as an ongoing workflow; the app exposing a tool does not itself grant provider permission.

For a later chat, call `bootstrap_input_get` to inspect the saved batch source, references, and documents. Use `bootstrap_document_import` to copy and extract a PDF, DOCX, or text screenplay into the same app input, then review the extracted text before asking for the app's outline request. For a generated background cross-unfold, call `background_unfold` on its registered background image ID; it uses the app's six-face detection and safety checks, saves the set, and marks the source processed. Import local stage art, panorama, or HDRI with `composition_background_import`; select or assign the returned ID with `background.select` or `room.panorama`. For pose key timing, `pose_joint_key.move/remove` affects one joint and `pose_key_group.move/remove` affects the folded pose row.

For sequential cuts, set `cutContinuity` on the next cut to `continue` (start from the previous final frame) or `same-space-new-angle` (retain cast and space with this cut's own camera). Finish the previous cut's video, register it, and explicitly select its representative with `asset_set_primary` before preparing or generating the next cut. The app extracts the selected video's final frame and uses the current cut order to resolve the dependency. Run `prompt_prepare` for the next cut only after that selection, preserve its `previousCut` instructions and actual `@` video/frame tags in both languages, then use `prompt.apply`. Inspect `magnific_compose_preview` to confirm the predecessor video and tags are present. Do not queue dependent cuts simultaneously. If an engine cannot accept the video reference, use its supported first-frame path or report the limitation rather than claiming full reference control.

For recurring character voices in Seedance, a reference can exist before the first video: call `voice_models_list`, ask for or infer a permitted model, dialogue, acting category, voice traits, voice gender, age range and language, then call `voice_generate` with the current project revision and a stable operationId. Categories include actor, singer, idol, announcer, weather presenter, radio host and ordinary speaker. Singer and idol style **spoken dialogue**; they do not synthesize singing. Pass `gender` and `ageRange` from the listed enum values; omit them when unspecified. Qwen3-TTS must first be installed through the app's local-model settings or `voice_engine_install`; inspect `job_get` until installation completes. VoiceDesign 1.7B accepts descriptive timbre guidance; CustomVoice 1.7B/0.6B uses a preset speaker (Sohee is the native Korean speaker), so gender or age directions might not change its fixed timbre. Wait for `job_get` to confirm the generated WAV was persisted. Alternatively, after selecting a completed cut video with `asset_set_primary`, call `voice_extract` on a clean passage spoken by that character alone. Never infer speaker identity from a mixed soundtrack. Both paths store the WAV under that character's `voice/` folder and make it the primary voice reference; `voice_select` changes the primary WAV later. Use `project_update` `character.update` for `voiceDescription` and `voiceDescriptionEn` on first appearance. Re-run `prompt_prepare` after a voice edit; the app's bilingual prompt rules and Magnific composition link the selected WAV by its actual `@` filename alongside the character sheet. Check `magnific_compose_preview` for the audio reference filename and matching tag, and verify the WAV path from the saved character. Audio-reference acceptance alone does not prove voice cloning or lip sync; review the clip.

## Keep the project complete

Every final or candidate image/video created outside the app during this chat must be imported with `media_register` into its character, background, or cut. Supply a stable `operationId`, the local source path, the prompt text, and the current project revision. Videos belong to cuts. If an output has no suitable target, create or identify one first. Save text-only prompts with `project_update`; save generation prompts with the imported asset as well. After import, read the project again and verify file path, prompt, and target. Select the approved representative with `asset_set_primary` and verify there is exactly one primary in that target's image or video shelf. Do not describe an external file as registered until that read-back succeeds.

Maintain separate project context per chat. A later chat resumes from the app's saved state and change history, rather than relying on the earlier chat transcript. When reporting progress, distinguish prepared prompts, submitted jobs, verified outputs, and persisted assets.

The source-level command guide is `docs/APP_CONTROL.md` in the AIMovieStorage repository. The connected server's live schema takes precedence over that document.

## Experimental native A2V (QA only)

Read `native_a2v_status` before submission. Only if it is ready, use `media_generate` with `engine:"ltx25"`, `options.ltx_a2v:"experimental"`, same-project `audioAssetId`, explicit `audioDurationSeconds`, optional `audioStartSeconds` (default 0), and optional `imageAssetId`/`endImageAssetId`. Audio must be local stereo PCM16 WAV. Offset and length round to the nearest sample (Python round-to-even ties); duration clamps at EOF. Visible frames are ceil(actual sample duration * fps); generation uses the next 8n+1 frame count at least as large. End image conditions the last visible frame, before zero audio padding. Both native stages freeze original conditioned audio; final MP4 uses lossless ALAC from the original selected samples and crops only the last video packet duration. Additional LoRA selections, masks, pose/structure guides, references, precision, seconds, steps, guidance, and ltx_quality are rejected rather than ignored. Omitted ltx_a2v preserves existing LTX defaults. This is not approved general production or proven lip sync; generated file creation is not quality review. Native cancellation waits for the isolated process to finish and skips attachment; no forced termination. OOM is a normal failed job, with only the own-process CUDA cache released. No automatic downloads or runtime install.

Audio asset IDs include existing saved composition music.path entries. If importing new local audio, reuse composition_music_import and composition_commit, then assets_list; native A2V does not add another importer.


## CPU planar overlay (prepared candidate)

Read planar_overlay_status first. media_planar_overlay uses same-project video/image IDs, exact source/replacement SHA256, complete frame-indexed TL/TR/BR/BL quads and actual CFR specs. It uses the independent CPU lane, never downloads tools or uses GPU, preserves original input and publishes a derivative. Results remain unregistered with registrationRequired:true; honor the current explicit registration/install hold. Review before separately authorized media_register(makePrimary:false). S02 non-text is allowed; S03 requires declared exact 한국사 raster, which still needs human glyph review. See docs/PLANAR_OVERLAY.md.


## 원본 보호 CPU 편집 (준비 후보)

protected_edit_status를 읽고 media_local_edit를 사용한다. 명시적 같은 프로젝트 선택/보호 이미지 ID와 SHA256, 원본/crop 매핑이 필요하다. 보호가 우선하며 정확 문자 레이어가 보호에 걸리면 자르지 않고 거절한다. 자동 의미 분할·글자 인식·새 모델·GPU 사용은 없다. 결과는 비대표·미등록이고 검수 후 별도 허가된 media_register(makePrimary:false) 또는 기존 comfy_masked_compose를 재사용한다. 현재 앱 쓰기/설치 보류를 지킨다. docs/LOCAL_PROTECTED_EDIT.md 참고.
