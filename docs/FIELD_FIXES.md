# 현장 문제 재검토와 수정 범위

현재 개발 브랜치의 기록입니다. 기존 릴리스·사용자 설치본에 반영되었다는 뜻은 아닙니다.

| --- | --- | --- |
| Krea의 negative 사용 때 색 번짐 | 기존 화면은 이미 Krea negative를 비웠습니다. 더 직접적인 문제는 guidance 0을 생략해 상류 기본 4.5로 실행하던 경로입니다. 0을 명시 전달하고 모델별 negative 조건을 정의했습니다. Z-Image Turbo 기본 guidance도 0으로 맞췄습니다. | 실제 호출 인자를 모의 파이프라인으로 검사했습니다. GPU 생성의 색 번짐 개선 여부는 미측정입니다. |

## 실측에서 추가로 발견한 문제

- MediaPipe 손 좌표의 `visibility`는 실제 검출에서도 0으로 반환됐습니다. 손 모델이 제공하지 않는 관절별 신뢰도를 믿으면 모든 손가락을 버립니다. 화면 안/밖 표지를 사용하며 이것을 가림 신뢰도라고 설명하지 않습니다.
- 손가락을 몸·손목보다 먼저 회전시키면 JSON 키 순서에 따라 자세가 달라집니다. 재생 함수가 몸 → 손목 → 손가락 부모 마디 → 자식 마디의 순서를 보장합니다.
- 새 모캡 시각에서 기존 손 값만 읽으면 그 사이의 수동 키가 사라집니다. 기존 손 키 시각도 함께 남깁니다. 몸과 손이 하나의 이징을 공유하므로 기존 곡선까지 완전히 같다는 보장은 하지 않습니다.
- 몸 전체가 오검출되어 이웃 프레임으로 복원된 순간에는 잘못된 원본 손 좌표도 적용하지 않습니다.
- 모캡 결과 파일의 경로 목록도 앱 데이터 폴더에 보존합니다. 결과 JSON과 목록 저장을 모두 확인해야 완료로 표시합니다. 아직 열지 않은 작품의 목록을 유지하고, 다른 origin의 기록과 합칠 때 삭제한 항목이 다시 나타나지 않도록 처리합니다.

## 다음 검증

1. SAM full 모드의 실제 전신 영상에서 손 정확도·추론 시간·최대 RAM/VRAM을 측정합니다. 손가락 함께 분석 옵션을 끈 결과와 비교합니다.
2. 손이 작은 군무, 가림, 교차, 좌우 반전 영상을 사용해 사람·손 배정의 실패율과 기존 키 보존을 점검합니다. 이번 MediaPipe 실측은 공식 손 사진과 그 사진을 이어 만든 짧은 영상입니다.
3. Krea의 동일 입력·seed 비교로 색 번짐 개선을 확인하고, 그 뒤 재질·환경 조명 비교를 진행합니다. 프롬프트 변경만으로 개선되었다고 단정하지 않습니다.

앱 조종기와 메모리 정리 정책의 별도 검증 범위는 [APP_CONTROL.md](APP_CONTROL.md)에 있습니다.
