# 로컬 LTX/Wan 목표 길이 계약

`seconds`는 출력 길이이며 모델 생성 길이와 구별합니다. fps는 그대로 유지합니다. 목표 프레임 `N = seconds × fps`가 양의 정수가 아니면 정확 길이를 만들 수 없으므로 오류로 중단합니다. 반올림, 속도 변경, 보간, hold로 요청을 바꾸지 않습니다.

모델의 시간 압축 단위 `s`는 Wan=4, LTX=8입니다. `G=max(s+1, ceil((N-1)/s)×s+1)`개의 프레임을 모델에 요청하고 정확히 G개의 디코딩 결과가 있는지 검사합니다. 출력은 원래 순서의 `[0,N)` 프레임만 동일 fps로 저장합니다. 부족하거나 예상보다 많은 모델 결과는 성공으로 보고하지 않습니다. 메타데이터 `frames`는 실제 저장 프레임 수이며 `seconds_video=frames/fps`를 소수 두 자리로 숨기지 않습니다. `duration_contract`에는 원요청, 목표/생성 수, 제외한 꼬리 수, 속도 유지 여부를 담습니다.

12초·16fps: N=192. Wan/LTX G=193. 프레임 0~191을 16fps로 저장하여 정확히 12초입니다. 12.1초·16fps는 193.6프레임이므로 오류입니다. 예전 189프레임 결과를 새 생성 없이 192프레임으로 늘릴 수 있다고 주장하지 않습니다.

LTX 구조 참조는 목표 구간 N만 읽고 생성용 꼬리 G−N만 마지막 참조로 채웁니다. 원본 참조의 시간을 넘겨 읽거나 참조 재생 속도를 변경하지 않습니다. 이 꼬리는 출력에서 제외됩니다. 메타데이터에 `generation_padding_frames`를 기록합니다. 2단계 생성도 동일 G로 진행한 다음 최종 디코딩 결과에 한 번 적용합니다.

끝 조건의 실제 시간 위치는 `end_condition_contract`에 별도로 기록합니다. 설치 Wan 공개 API는 `last_image`를 G−1에 고정하고 임의 위치 인자를 제공하지 않습니다. 설치 Diffusers LTX의 index는 latent 단위이며 0 또는 픽셀 시간 `(index−1)×8+1` 격자만 지정할 수 있습니다. N−1이 이 격자에 있으면 정확한 양의 인덱스를 단일/2단계 모두에 전달합니다. 격자 밖이면 기존 −1 조건을 유지하되 출력 끝과 다름을 로그/메타데이터에 명시합니다. −1의 실제 시간도 격자 매핑으로 계산하며 “꼬리에 잘린다”를 일괄 표시하지 않습니다. 193 생성에서 −1은 시간185이며 12초/16fps 출력 끝191과 다릅니다. native A2V는 별도의 픽셀 frame_idx API로 기존 마지막 표시 프레임을 지정합니다.

정확한 API 시간 위치와 최종 디코딩 픽셀/장면 정확성은 다릅니다. `decoded_final_frame_accuracy_verified`는 false이며 실제 GPU/품질 검사 없이는 합격하지 않습니다. 임의 프레임 인자를 만들어 넘기거나 끝 이미지를 출력에 붙이지 않습니다. 모델의 개인 메서드를 monkey patch하거나 설치된 Diffusers를 수정하지 않습니다.

## 원음과 기존 native A2V 경로

현재 일반 Diffusers LTX/Wan 저장 경로는 영상만 저장하며 원음 입력을 새로 추가하지 않았습니다. 별도 native A2V의 오디오 기준 생성/패딩/원음 보존 로직은 변경하지 않습니다. 원음을 영상에 결합할 때는 목표 구간과 같은 길이의 원음 전체를 원래 sample rate·sample 순서로 보존해야 합니다. `-shortest`, fps 조절, tempo/resampling, 목표 구간 밖의 원음 삭제를 자동으로 적용하지 않습니다. 원음의 보존 구간이 목표 길이와 다르면 정확 길이와 전체 원음 보존을 동시에 만족시킬 수 없으므로 별도 요청/구간 선택 없이는 거부해야 합니다.

기존 CPU media_edit의 명시적 프레임 구간 편집을 사용한 합성 회귀는 193프레임 영상과 12초 stereo PCM16/48kHz 원음을 함께 구성하여 [0,192) 출력에서 576000개 PCM 샘플 전체가 동일하고 침묵 추가 0임을 확인합니다. 이는 일반 생성 경로에 새 오디오 mux 기능을 연결했다는 의미가 아닙니다. 압축 바이트 복사나 임의 코덱/샘플 형식 보존을 보장하지 않습니다.

## 검증과 배포

GPU·실제 제작 소스를 사용하지 않는 `test_video_frame_contract.py`와 관련 LTX/Wan/구조/2단계/CPU media_edit 회귀가 계약을 검증합니다. 기존 Stage197/206 결과, 평가 플래그, 앱 설치, 외부 MCP 연결, 모델 캐시와 OS 설정을 변경하지 않습니다. 새 준비 후보는 `endpoint-contract-implementation`이며 이전 후보와 EXE는 보존합니다.
