# Workflow admission validation

The V6 cumulative source preserves the reviewed V1/V2 owner adapters, native audio/video storage and memory policy, prompt model routing, workflow library/controller/scene batch integration, and project/model/file-SHA scoped authorization. The shared UI/native timebase resolver validates actual bindings first and uses reviewed fixed graph inputs only when corresponding semantic slots are absent. Conflicting, invalid, missing or ambiguous values are rejected. Caller expected FPS/duration is never treated as graph evidence.

The 0.3.27 r3 engineering validation reported 1,233 app CPU tests passing with one opt-in actual GPU test skipped, 75 owner CPU tests passing, and 291 native tests passing with eight live tests ignored. Independent read-only review found no Blocking, High or Medium defect in the earlier V6 delta; the later tutorial and graceful-shutdown delta has CPU coverage and no independent r3 review claim. These checks do not establish installed UI behavior or model output quality. Publication checks are recorded outside the source repository.

The packaged runtime preset registry contains only Music3 instrumental smoke. Other single-model or same-model multi-role paths require trusted exact registry/source/schema/weight data, current environment facts, same-project native references and the user's scoped authorization. Different-model multiple roles, maskVideo, and unreviewed custom TTS/SDNQ remain blocked. Offline design catalog entries are not runtime grants or enabled presets.

Actual model generation, GPU execution, real-media submission/history/registration, listening/visual quality and installed app restart have not been validated by publication. Actual update evidence is required before source publication; installation is performed separately from publication. No release tag or updater manifest is changed by this source-only update.

Manifest-hashed native A2V SDK files and their upstream licenses retain exact bytes across Windows checkouts and public export. The disk mmap/pread admission and quality limits in [the checkpoint policy](NATIVE_A2V_CHECKPOINT_READ_POLICY.md) continue to apply.

The r3 tutorial adds the Comfy selection/import/reference/prompt/output/job flow, revises retired instructions, and updates translations. Normal GUI close, maintenance preparation/quit and worker-stop controls use idle-only quit_idle plus EOF for app-owned worker handles, with a bounded asynchronous exit check. Active jobs, pending requests, installation, prefetch, unsaved editors and Comfy queues block shutdown. Timeout or cancellation retains the app and surviving handles; duplicate preparation is rejected. This targeted graceful path has no force-kill fallback and does not claim to replace unrelated legacy error/uninstall cleanup policies. Four stdlib CPU child-process protocol cases test the actual worker source without importing Torch or loading models. Live installed GUI/worker behavior remains a separate validation requirement.
