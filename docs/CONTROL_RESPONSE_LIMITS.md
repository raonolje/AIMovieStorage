# 큰 프로젝트의 MCP 응답

프로젝트·구도의 조회, 편집 결과, 변경 조회, 저장 결과는 `detail: "summary"`가 기본이다. `detail: "full"`로 전체 상태를 요청할 수 있지만 응답 크기 제한은 그대로 적용된다.

요약은 `draft`/`state`의 기존 구조와 인물·씬·컷·방·트랙 ID, 카메라 설정을 유지한다. 100개 이하의 키는 시각·자세와 함께 제공한다. 100개를 넘는 키 배열은 응답에서 비우고 같은 트랙의 `keyCount`/`keyTimeRange` 또는 `customKeyCount`/`customKeyTimeRange`에 개수와 첫·끝 시각을 적는다. 별도의 `projection.omitted`에도 생략 경로와 이유를 표시한다.

내장 base64 이미지, 긴 문자열, 큰 배열도 응답 예산에 맞춰 줄인다. `projection.truncated: true`는 일부 값이 생략됐다는 뜻이다. **요약의 빈 배열·빈 문자열을 원본 데이터나 삭제 명령으로 해석하면 안 된다.** 실제 파일 저장과 undo 기록은 전체 원본을 사용한다. 이미지 확인에는 `composition_capture`/`asset_preview`, 편집에는 각 도구의 명시적인 명령을 사용한다.

리비전과 오래된 요청 거절은 요약 전의 전체 상태를 기준으로 한다. 생략된 모캡 키를 사람이 고쳐도 리비전이 바뀌고 예전 리비전의 수정 요청은 거절된다. 변경 본문이 줄어들면 `fullSnapshotRequired`와 생략 표시를 확인한다. 전체 상태가 제한을 넘으면 요약을 다시 읽고, 꼭 필요한 키의 세부 확인은 현재 편집 화면에서 수행한다. 임의 크기 자료를 모두 반환하는 페이지 조회 API는 아직 제공하지 않는다.

일반 도구 결과는 JSON 본문 4MiB를 넘으면 `response_too_large`를 반환한다. 같은 내용이 MCP의 text와 structuredContent 양쪽에 들어가기 때문에 네이티브의 32MiB 전송 제한보다 작은 예산을 둔다. 네이티브도 초과 응답을 전송 도중 자르는 대신 작은 오류 프레임으로 바꾼다. 제한을 늘려 대형 복제를 반복하지 않는다.

편집 결과를 전체로 요청했다가 `response_too_large`가 나면 **편집 자체는 이미 적용됐을 수 있다.** 반환된 projectId/sessionId/revision/persisted 정보가 있으면 확인하고, `detail: "summary"`로 다시 조회한 뒤 다음 명령을 결정한다. 같은 편집을 바로 재실행하지 않는다.

CPU 회귀는 5인 × 1,983키 프로젝트의 요약·원본 보존·오래된 리비전 거절, 실제 도구 등록부의 큰 응답 오류, 큰 구도 저장·undo/redo와 변경 이력 헤더 보존을 검사한다. 네이티브의 큰 실제 프로젝트 왕복은 별도의 실행 검증 대상이다.
