# H3 영상 레퍼런스 구간 선택

2026-09-23. 전체 참조와 앞 5초 선택의 입력 계약이다. 자동으로 원본을 잘라 결과를 바꾸지 않도록 H3 영상 참조가 있는 요청은 구간을 명시해야 한다.

## 화면과 MCP 계약

로컬 영상 생성에서 H3와 영상 레퍼런스를 함께 고르면 `앞 5초만 (최대)` 또는 `전체 영상`을 선택한다. 기본은 미선택이며 선택해야 생성 버튼이 활성화된다. 원본 영상 목록이 달라지면 다시 선택한다. 모든 영상 레퍼런스에 같은 선택이 적용되고, 그림·별도 오디오 참조는 바뀌지 않는다. 원본 파일은 수정하지 않는다.

`media_generate` 요청의 `options.reference_video_range`:

```json
{
  "engine": "minimaxh3",
  "referenceAssetIds": ["현재 프로젝트의 영상 에셋 ID"],
  "options": {
    "prompt": "장면 설명",
    "seconds": 5,
    "reference_video_range": "first5s"
  }
}
```

예시는 구간 관련 필드만 보인 것이며, 기존의 projectId·target·operationId도 필요하다. `full`은 전체를 읽는 기존 경로다. 다른 엔진이나 영상 참조 없는 요청에 이 옵션을 주면 거절한다. **기존 호출도 H3 영상 참조가 있다면 이 선택값을 추가해야 한다.** 대기열 재개와 Python 워커의 모델 로드 전 검증에도 같은 요구를 적용한다. 에셋 ID 제한을 유지하므로 새 임의 파일 경로 입력은 없다.

## 길이와 처리시간의 의미

화면은 각 파일의 컨테이너 길이를 `원본`으로 표시한다. 읽을 수 없으면 확인하지 못했다고 표시하며, 생성 결과 길이와 혼동하지 않는다. `선택`은 전체 또는 최대 앞 5초다. 화면의 소수점 길이는 미디어 메타데이터이며, 워커 디코드 프레임 수와 작은 반올림 차이가 날 수 있다.

앞 5초는 PyAV에서 읽는 프레임의 시각·개수를 함께 제한한다. 전체 프레임을 먼저 메모리에 올린 뒤 슬라이스하지 않는다. 원본 FPS를 유지하고 소리도 같은 선택 길이까지 읽는다. 5초보다 짧은 영상은 연장하거나 반복하지 않는다. 전체는 기존 공식 `MiniMaxH3VideoReference.from_file`을 사용한다.

현재 설치된 공식 H3는 참조를 24fps로 정규화한 뒤 **생성 영상의 프레임 수까지만** 조건으로 사용한다. 따라서 `전체`여도 긴 원본의 뒤쪽이 모두 조건에 들어간다는 뜻은 아니다. 선택 길이를 바꾸는 앱 동작과 이 모델 규칙을 화면에서 함께 밝힌다.

작업 완료의 `meta.reference_videos` 및 시작 전 진행 메시지에 다음을 기록한다:

- `reference_index`: 그림·소리를 포함한 전체 참조 목록의 0부터 시작하는 위치.
- `range`: 선택값.
- `source_reported_seconds`: 컨테이너가 보고한 원본 길이. 모르면 null.
- `decoded_frames`, `decoded_seconds`, `source_fps`: 실제 디코딩해 참조 객체에 넣은 프레임과 그 FPS 기준 길이.
- `conditioning_frames`, `conditioning_seconds`, `conditioning_fps`: 설치된 H3의 24fps 정규화·출력 길이 제한 규칙을 적용한 조건 프레임 수와 길이. 모델 내부의 영상 잠재 벡터·토큰 개수와는 다르다.
- `has_audio`, `audio_seconds`: 참조 객체에 전달한 오디오의 존재와 표본 수 기준 길이.

## 확인

- 프런트엔드 33개 시험 통과: 구간 필수·잘못된 값/엔진 거절, first5s/full 전달, 작업 결과 메타 보존, 기존 생성 저장·재전송·취소 회귀.
- 새 Python 6개 통과: 명시 선택, 미지원 조합, 5초 뒤 디코드 호출 금지, 실제 6초 영상의 5초 프레임/소리 제한 및 원본 해시 보존, 짧은 2초 영상 무연장, 전체의 공식 디코드 결과 일치.
- 실제 CPU 시험은 H3 설치 환경에서 작은 16×16 합성 MKV/소리로 실행했다. CUDA는 숨기고 Hub 네트워크는 끈 상태였다.
- 기존 Python 제어 정책 14개 및 `pnpm check` 통과.

GPU 생성과 앱 화면은 이 CPU 시험으로 검증하지 않았다. 다음 실측은 같은 소스로 구간 선택을 명시하고 작업 결과·이미지/영상 품질·걸린 시간을 별도로 확인해야 한다.

후속 실제 생성에서 확인한 RoPE 장치 불일치와 별도의 소형 모듈 회귀는 [H3 장치 배치](h3-device-placement.md)에 기록했다. 참조 구간 시험과 전체 생성 성공을 구분한다.
